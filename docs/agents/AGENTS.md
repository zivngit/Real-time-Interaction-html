# AGENTS.md (AI 助理協作與開發規範)

本文件是 `Real-time Interaction html` 專案中所有 AI 開發助理 (Agents) 的最高行為準則。在執行任何程式碼編寫、架構調整或除錯任務前，請務必詳閱並嚴格遵守以下規範。

---

## 1. 專案文件導覽與連動規則

在 `.\docs\agents` 目錄下，包含維持專案運作的核心文件。AI 助理在執行任務時，必須根據任務性質查閱或更新以下對應文件：

*   **`AGENTS.md`** (本文件)
    *   **用途**：定義 AI 助理的工作流程、測試與交付標準。
*   **`TODO.md`**
    *   **用途**：專案的任務追蹤清單。
    *   **Agent 職責**：在開始新工作前應優先查閱此文件以確認當前任務；任務完成後，必須主動更新該文件，標記已完成項目或補充後續待辦事項。
*   **`CALL_GRAPH.md`**
    *   **用途**：記錄系統架構、模組依賴關係與函式呼叫路徑。
    *   **Agent 職責**：當新增、重構或刪除具有重要邏輯的函式與類別時，必須同步更新此文件，確保系統架構圖與實際程式碼保持一致。

---

## 2. 注意事項與文件維護規則

為確保專案品質與開發流程的穩定，所有 Agent 在執行任務與修改文件時，請嚴格遵守以下注意事項：

-   **版本控制與追蹤**：每次改動完成後，都必須創建一個對應的 Git commit，以便後續追蹤和回滾。
-   **測試與品質保證**：每次改動後，都必須編寫或更新相關測試，並在交付給用戶前，確保所有測試和驗證全部通過。
-   **工作完成報告**：每次新增、修改、移動或刪除文件時，必須將工作完成報告輸出至指定路徑 `.\docs\agents\reports`，並在該報告中詳細列出文件路徑與修改摘要；報告格式遵循 `reports/REPORT_TEMPLATE.md`，檔名慣例為 `YYYY-MM-DD-<任務摘要>.md`。
-   **報告自身排除**：文件異動表僅記錄本次工作影響的其他文件；不必將工作報告檔案本身列為「新增 | 記錄本次文件異動」。

---

## 3. 標準作業流程 (SOP)

為了將上述規則具體化，Agent 的單次工作週期應遵循以下步驟：

1.  **任務理解 (Plan)**：讀取 `TODO.md`，理解需求，並檢視 `CALL_GRAPH.md` 中是否有相關的架構限制。
2.  **執行與測試 (Execute & Test)**：撰寫程式碼並執行單元/整合測試，確保完全符合品質保證要求。
3.  **文件同步 (Document)**：根據程式碼的變更，同步更新 `CALL_GRAPH.md`（若涉及架構變動）與 `TODO.md`（標記完成）。
4.  **提交與報告 (Commit & Report)**：
    *   生成具描述性的 Git commit。
    *   於 `.\docs\agents\reports` 目錄下產生本次任務的 Markdown 工作完成報告（格式遵循 `REPORT_TEMPLATE.md`）。
